# Boss 正常用户稳定采集改造

## Goal

让 Boss 自动采集尽量沿用真实用户浏览路径：复用可见 Chrome 的持久资料、允许用户在风控/登录验证时人工接管，并优先采集页面自然产生的岗位列表/详情数据，降低正常求职账号被误判的概率。

## Requirements

- Boss 登录和 Boss 自动采集必须共用独立持久浏览器资料目录，不再每次用临时浏览器只注入 cookies/localStorage。
- Boss 采集遇到 403、访问异常、验证码页或安全检查页时，不应立刻关闭浏览器；应暂停并提示用户在当前浏览器窗口完成登录/验证/正常浏览，然后自动重试。
- Boss 采集应支持正常页面驱动路径：打开 Boss 搜索页，按关键词和筛选条件访问/翻页，并复用页面自然产生的岗位列表响应来入库。
- 保留现有接口采集能力作为兼容路径，但默认行为必须更接近正常用户浏览：可见浏览器、持久资料、限速、单页顺序采集。
- 不实现验证码破解、token 逆向、TLS 指纹伪造、代理池绕过等高风险能力。
- 采集日志要能让用户区分：正在等待人工验证、验证恢复后继续、接口/页面真实失败、用户主动停止。
- 既有 Boss 多城市、关键词、筛选、`maxPages`、`maxJobs`、去重和岗位详情写入能力不能回退。

## Acceptance Criteria

- [ ] Tauri 登录命令为 Boss 传入 `boss-browser-profile` 一类的持久资料目录。
- [ ] Tauri 自动采集命令为 Boss 传入同一个持久资料目录。
- [ ] Worker Boss 自动采集启动浏览器时使用 payload `user_data_dir`。
- [ ] Worker Boss 自动采集遇到风控响应时进入等待/重试循环，而不是直接 `FINISHED + ERROR` 退出。
- [ ] Worker Boss 自动采集至少能从自然页面产生的 joblist 响应中恢复岗位列表数据；直接接口失败时不再是唯一采集路径。
- [ ] 契约测试覆盖 Boss 风控暂停重试、Boss profile 传递、自然响应回退/优先路径。
- [ ] 构建、类型检查和相关 Node/Rust 测试通过，或明确记录不可运行原因。

## Constraints

- 改动可以重构，但必须围绕 Boss 正常用户稳定采集，避免无关 UI/数据库大改。
- 不回滚当前工作树已有无关改动。
- 所有跨层 payload 字段要保持单一事实源，避免前端、Rust、worker 各自猜字段。
