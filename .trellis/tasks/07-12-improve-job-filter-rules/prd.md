# 继续优化岗位过滤规则

## Goal

把本机实际生效的宽松三段提示词替换为严格精准规则，强化同一具体岗位的证据绑定和非招聘门禁，并立即重算历史岗位，使职位库只保留符合用户目标的 Go/Java 后端、AI Agent/LLM 应用开发和 AI 工程化研发岗位。

## Background

- 用户要求岗位判断尽量由三个可编辑提示词决定，代码不得隐藏英语、远程、学历、技术方向等个人偏好。
- 上一轮已修复两个已知误判：要求英语交流/全英面试的渣打岗位应 `filtered`；AI 模拟面试产品介绍不是招聘帖，应被来源门禁或采后 AI 过滤。
- 上一轮真实模型只读烟测中，这两个样本均已得到 `filtered`，说明当前默认精准模板与新判断协议对已知样本有效。
- 现有自定义 profile 不会被默认模板自动覆盖；用户需要主动应用精准模板并保存、重算。继续优化前需要区分“规则内容仍不够准”和“本地仍在使用旧自定义文本/旧判断结果”。
- 只读查询本机实际默认 profile 后确认，当前生效文本仍是旧版宽松自定义内容：正向规则包含“AI 相关工作”，排除规则包含“我不会的开发语言”，风险规则仍使用“软排除”措辞；不确定策略为 `filtered`。
- 最近 20 个 AI `passed` 结果中已发现多类明显边界误放行：视频推荐算法岗、AI 产品经理、全栈岗、“优先坐班/优秀可远程”岗位、个人自我介绍/寻项目合作帖等被标为 `recommended`。
- 这些误放行与当前生效规则的模糊范围一致，不能据此判断新精准模板本身失效；首先需要解决“新模板未应用到现有 profile”以及升级后的历史结果重算问题。

## Requirements

- 保持三个可见文本框作为个人岗位偏好的唯一事实源。
- 继续保留代码拥有的通用真实招聘内容门禁，但不得向隐藏 prompt 增加个人偏好。
- 用户已明确授权：直接将本机当前默认 profile 的 `aiPreferredText`、`aiRejectedText`、`aiRiskText` 替换为代码中的新精准模板，不需要升级提示、差异预览或再次确认。
- 替换前必须生成本机 SQLite 一致性备份并在任务证据中记录路径；`aiUncertainStrategy` 保持当前 `filtered`，其他 profile 字段不得改变。
- 三段文本替换成功后立即对现有需要 AI 内容判断的历史候选岗位执行批量重算，使列表结果马上按新规则更新。
- 确定性黑名单、人工否决、负向沟通状态等硬拦截岗位不得被批量 AI 重算重新放行；批处理失败必须保留逐岗位失败信息并可安全重试。
- 新增的过滤行为必须有明确正例、反例和信息不足样本，避免只针对单个关键词打补丁。
- 明确排除规则优先于正向偏好；信息不足才使用不确定策略。
- 新精准文本必须明确排除：产品经理/产品运营、纯推荐算法或算法研究、开发者关系/Developer Advocate、以智能合约或 Web3 为核心职责、兼职、外包式项目合作或个人寻合作；这些岗位不能仅因出现 AI、Agent、Go、远程等词被推荐。
- 最终正向范围仅保留 Go 后端、Java 后端、AI Agent/LLM 应用开发和 AI 工程化研发岗位。
- 多岗位帖子只有在能从正文清楚拆出至少一个完整符合全部规则的具体岗位，并能将岗位职责、工作方式、英语/学历等条件明确归属于该岗位时才允许进入候选；如果要求混杂、无法确认排除条件属于哪个岗位，则整帖 `filtered`。
- 手动保存/批量重算属于本地维护操作，必须关闭 Telegram 等外部通知；正常采集完成后的既有通知行为保持不变。
- 通用内容门禁应识别个人自我介绍、寻项目合作、接项目/兼职合作等非雇佣招聘内容，但不得把产品经理、算法、Web3 等合法招聘类别硬编码为全局非招聘；这些个人排除项只存在于可见文本中。

## Acceptance Criteria

- [x] 确认当前本地实际生效的三段提示词及不确定策略，不把默认模板误当作已保存配置。
- [ ] 代码默认模板与本机默认 profile 均替换为同一版严格文本，本机不确定策略仍为 `filtered`，其他 profile 字段保持不变。
- [ ] 建立剩余误判样本集，至少覆盖算法岗、产品经理、全栈岗、条件式远程、个人寻合作、多岗位混合帖、合格岗位和信息不足场景。
- [ ] 每个新增或调整的规则均来自用户可见文本，隐藏协议只负责顺序、证据和结构化输出。
- [ ] 推荐结果的招聘真实性、目标职责、工作方式及其他必须条件必须来自同一个具体岗位，不能跨岗位拼接证据。
- [ ] 提示词单测能验证三段规则原样进入最终请求，且隐藏协议不包含个人偏好；来源门禁测试覆盖自我介绍/项目合作反例。
- [ ] 本机数据库在修改前完成一致性备份；替换后立即完成历史岗位批量 AI 重算，失败项有明确记录且可重试。
- [ ] 本次手动重算没有发送 Telegram；正常采集通知路径的测试保持通过。
- [ ] 已知误推荐样本重算后不再是 `recommended`，合格的严格全远程目标研发岗仍可保持 `recommended`。
- [ ] 过滤链路回归测试与全量构建通过。

## Out of Scope

- 不新增自动投递、自动打招呼或外部消息发送。
- 不把个人英语、远程、学历或技术方向偏好重新硬编码进代码。
- 代码层面不新增对其他机器或其他自定义 profile 的静默覆盖；本次只修改用户明确指定的本机默认 profile。
