# 简历库与岗位关联

## Goal

把现有“简历工作区”替换为主导航里的“简历库”，让用户把 Markdown 简历作为可管理资产保存、指定默认简历，并把简历和职位库岗位建立清晰的一对多关系。岗位关联简历后，所有需要简历信息的后续能力优先使用岗位关联简历；没有关联时使用用户手工指定的默认简历。

## User Value

- 用户可以维护多份面向不同岗位方向的简历，而不是把简历藏在设置或单个工作区里。
- 用户能从简历看到已关联岗位，也能从职位库岗位反向跳到对应简历。
- 打招呼、简历匹配、投递材料等后续“用简历”的能力有稳定的简历来源优先级，不需要用户每次重新选择。

## Confirmed Decisions

- 简历库是简历管理的唯一入口，放在主导航。
- 直接替换现有“简历工作区”入口；不再把“简历工作区”作为主要产品概念暴露给用户。
- 简历正文以粘贴 Markdown 文本为第一版输入方式。
- 不做旧“简历工作区”或设置页简历文本的自动迁移；简历库从空状态开始。
- 默认简历由用户手工指定，不自动取最新编辑简历。
- 一个简历可以关联多个岗位。
- 每个岗位只维护一份主关联简历。
- 岗位已关联简历时，简历相关动作优先使用岗位关联简历；岗位未关联时回退到默认简历。
- 编辑简历只更新简历本身，关联关系保持不变。

## Requirements

- 用户可以进入主导航“简历库”页面，看到简历列表。
- 用户可以新建简历，填写标题，粘贴 Markdown 简历正文并保存。
- 用户可以编辑简历标题和正文。
- 用户可以删除简历；删除前必须确认。
- 用户可以将某份简历设置为默认简历；系统只允许一份默认简历。
- 用户可以在简历详情中查看该简历关联的岗位列表。
- 用户可以在简历详情中点击“关联岗位”，弹出推荐查看岗位列表并选择一个或多个岗位保存关联。
- 关联岗位时，如果某个岗位已有关联简历，保存后该岗位主关联简历切换到当前简历。
- 用户可以从职位库中已关联简历的岗位一键跳到简历库，并定位到该简历。
- 用户可以从职位库中未关联简历的岗位发起关联，或进入简历库后选择简历建立关联。
- 设置页不再作为简历正文维护入口；简历相关设置应收敛到简历库或后续专门能力里。

## Acceptance Criteria

- [ ] 主导航出现“简历库”，现有“简历优化/简历工作区”入口被替换或重定向。
- [ ] 简历库空状态清楚展示，并提供新建简历入口。
- [ ] 新建简历可以输入标题和 Markdown 正文，保存后出现在列表。
- [ ] 编辑简历后，标题和正文持久化；原有关联岗位不丢失。
- [ ] 删除简历后，该简历不再出现在列表；相关岗位不再指向已删除简历。
- [ ] 用户可以手工设置默认简历；列表和详情能看出哪份是默认。
- [ ] 简历可以关联多个推荐查看岗位；每个岗位只能保存一份主关联简历。
- [ ] 简历详情能列出已关联岗位，并能打开岗位详情或跳回职位库定位岗位。
- [ ] 职位库岗位卡能展示关联简历状态，并能跳转到简历库定位对应简历。
- [ ] 生成打招呼等需要简历的后端能力按优先级解析简历：显式传入 > 岗位关联简历 > 默认简历。
- [ ] 未配置默认简历且岗位未关联简历时，需要简历的功能给出明确提示。
- [ ] `npm run build` 通过。

## Out Of Scope

- 不做旧设置页简历文本或旧简历工作区数据的自动迁移。
- 不做富文本编辑器、Markdown 预览增强、版本历史或简历模板市场。
- 不做一岗多简历并存、简历优先级排序或 A/B 投递版本管理。
- 不做自动投递、自动发送简历或自动开聊。

## Open Questions

- 无阻塞开放问题。进入实现前需要用户确认本规划即可。
