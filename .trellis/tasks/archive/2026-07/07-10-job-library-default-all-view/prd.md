# 职位库默认展示全部入库

## Goal

将职位页默认分区从“推荐查看”调整为“全部入库”，让用户进入职位库时直接看到完整职位集合。

## Background

- `src/pages/Jobs.vue` 当前把默认分区初始化为 `recommended`，首次进入 `/jobs` 且列表为空时再次调用 `applyBucket("recommended")`。
- “推荐查看”只展示采后规则通过且尚未处理的候选岗位，因此用户观察到职位展示不全。
- 后端 `list_job_candidates` 对 `recommended` 添加 `eligible = 1`、推荐 bucket 且未处理的过滤条件；`all` 不添加分区过滤。
- 已通过前端契约测试和 Rust 分区查询测试确认：职位数据仍在库中，可通过“全部入库”查看。

## Requirements

- 无指定岗位路由参数进入 `/jobs` 时，默认选择“全部入库”。
- 默认请求使用 `bucket = all`，处理状态为 `all`。
- 保留“推荐查看”“待确认”“已过滤”“已处理”等分区及现有筛选语义。
- 从路由参数聚焦指定职位的行为保持不变。
- 使用最小改动，不修改后端分区 SQL 或职位状态业务规则。

## Acceptance Criteria

- [x] 直接进入 `/jobs` 时默认分区标题为“全部入库”。
- [x] 默认列表包含推荐、待确认、已过滤和已处理职位，不再只显示已通过职位。
- [x] 用户仍可手动切换“推荐查看”等分区，现有查询语义不变。
- [x] 指定 `jobId` 路由聚焦行为保持不变。
- [x] 前端契约测试、Rust 分区查询测试和前端构建通过。
- [x] 完成通用代码 Review，未遗留当前范围内明确问题。

## Out of Scope

- 不调整采后规则、AI 审核或人工审核状态含义。
- 不修改后端各分区查询条件或职位数据。
- 不做与职位页默认分区无关的 UI 重构。

## Product Decision

- 默认分区选择“全部入库”，接受默认列表信息量增加；“推荐查看”继续作为可手动选择的精简视图。
