# 提升产品 UI 颜值与移动体验

## Goal

把 JobPilot 从“干净可用的后台工作台”提升到更有产品感、更精致、更适合桌面与移动预览的求职效率工具。第一轮聚焦全局视觉系统、响应式导航、交互尺寸和已发现的可访问性缺口，不改变采集、职位、简历或设置业务逻辑。

## User Value

- 用户打开产品时能感到这是一个完整、可信、有审美的求职工作台，而不是临时拼出来的表单集合。
- 移动宽度预览时核心内容应尽快出现，不再让完整侧边栏占满首屏。
- 主要按钮、输入、选择器和导航更容易点击，状态反馈更清楚。
- 视觉语言统一，有明确品牌气质，同时保持工具型产品所需的信息密度。

## Confirmed Facts

- 技术栈是 Vue 3 + Vite + Tailwind + Tauri，前端入口为 `src/App.vue`、`src/styles/tailwind.css`、`src/pages/*`、`src/components/*`。
- 路由包含 `/crawl`、`/crawl-config`、`/jobs`、`/resume-library`、`/settings`。
- 现有 UI 已使用语义色 token、Lucide 图标、焦点 ring、禁用态和响应式容器。
- 视觉审查发现：桌面和 375px 移动宽度无横向滚动、无控制台错误，每页有 1 个 h1。
- 主要问题：移动端完整侧边栏占据首屏；整体白灰蓝偏平；基础按钮/输入/导航多为 36-38px 高；设置页 Model 输入缺少可关联 label；仅有 light color scheme。
- `npm run build` 当前通过，工作区创建任务前为干净状态。

## Requirements

- 全局视觉系统必须更有品牌辨识度，减少一味白底灰线的平铺感。
- 桌面端仍保持工作台型产品的信息密度和左侧导航，不做营销页式大幅装饰。
- 移动端必须压缩导航占用，首屏应优先展示当前页面标题与核心内容。
- 通用按钮、输入、图标按钮、选择器触发器应提升到更接近 44px 的触控目标，同时避免桌面过度臃肿。
- 页面卡片、面板、空状态、警告条和弹层应有统一的阴影/边框/背景层级。
- 设置页 Model 输入必须有真实 label 或 `aria-label`。
- 保留现有业务逻辑、路由、组件接口和数据流。
- 使用现有依赖，不新增 UI 框架或图标库。
- 所有改动必须通过构建和浏览器烟测。

## Acceptance Criteria

- [ ] `/crawl`、`/crawl-config`、`/jobs`、`/resume-library`、`/settings` 在 1440px 桌面视口视觉统一，页面不显得空、散、过度灰白。
- [ ] 375px 移动视口不再由完整导航占满首屏；核心内容在首屏可见。
- [ ] 375px 和 1440px 视口均无横向滚动。
- [ ] 主要交互控件高度达到或接近 44px；因数据密度保留的小控件必须有合理视觉/语义补偿。
- [ ] 设置页 Model 输入不再被审查脚本识别为未标注字段。
- [ ] 没有新增未命名按钮、明显文字溢出、互相遮挡或控制台错误。
- [ ] `npm run build` 通过。
- [ ] 浏览器截图烟测覆盖桌面与 375px 移动宽度，至少覆盖核心 5 个路由。

## Out of Scope

- 完整深色模式。
- 全量页面信息架构重做。
- 新增业务功能、改后端/数据库/采集逻辑。
- 更换前端框架、引入大型 UI 组件库或动画库。
- Tauri 原生窗口壳、打包和图标资产重做。

## Open Questions

- 是否接受第一轮不做完整深色模式，只做高质量浅色工作台视觉升级。推荐答案：接受；这样能在本轮稳定交付视觉和可用性收益，后续再单独做深色主题。
