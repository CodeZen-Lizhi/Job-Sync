# 修复采集完成后的统计不准确

## Goal

让采集页顶部统计在自动采集和 AI 采后判断全部完成后，展示与本轮实际处理结果一致的数据，避免日志已有审核结果但“通过”等卡片仍显示旧值。

## Background

- 用户截图中顶部显示“总搜到 20、跳过 0、入库 20、通过 0”，但运行日志已经输出多条 AI 审核结果，并汇总“采后判断 11 个职位”。
- `src/components/crawl/CrawlRuntimePanel.vue:36-42` 直接从最近一条 `CollectionRun` 构造统计；“入库”当前计算为 `inserted + updated + duplicate`，“通过”读取 `run.recommended`。
- `src/lib/useCrawlPage.ts:1052-1110` 会逐个平台执行采集，并在每个平台结束后刷新 collection summary；所有平台结束后才统一执行 AI 采后判断，AI 完成后没有再次刷新 collection summary。
- `src-tauri/src/sidecar/mod.rs:429-431` 在 worker 结束时刷新 `collection_run` 的分桶计数并结束 run；该时点早于前端随后触发的 AI 采后判断，所以 `recommended` 等字段是采后判断前快照。
- `src/lib/useCrawlPage.ts:337` 只选择 `collectionRuns[0]` 作为顶部统计来源；多平台自动采集时，该值只代表最近一个平台 run，而不是用户触发的整轮自动采集。

## Requirements

- 顶部统计必须在 AI 采后判断结束后反映最终结果，不能继续展示采后判断前的分桶快照。
- “总搜到、未新增、新入库、通过”四个指标必须有一致且可解释的本轮口径。
- 顶部统计代表用户本次点击触发的整个多平台采集批次，不能把最近一个平台 run 误当作整个批次。
- 统计规则应收敛在可测试的数据层或单一聚合入口，不从运行日志文本反向解析数字。
- 保持现有职位采集、去重、AI 判断和通知业务规则不变。

## Acceptance Criteria

- [ ] 复现用例中，AI 日志汇总 11 个岗位后，顶部统计不再保留采后判断前的“通过 0”旧值。
- [ ] “通过”与本轮相关岗位最终处于通过状态的数量一致；AI 失败、待确认和不通过不计入通过数。
- [ ] “新入库”的展示值和辅助文案含义一致，不把更新或重复项称为新写入本地库；更新和重复项归入“未新增”。
- [ ] 单平台和多平台自动采集均有自动化检查，统计不会因只读取最后一个平台 run 而丢失前序平台数据。
- [ ] 采集为空、全部重复、部分 AI 失败时统计仍有确定口径且不报错。
- [ ] 完成前执行受影响测试、构建或类型检查，并使用通用代码 Review skill 审查改动。

## Out of Scope

- 不修改 AI 审核通过/不通过的业务判定规则。
- 不调整职位库筛选、岗位状态含义或 Telegram 通知内容。
- 不做采集页无关的 UI 重构。
